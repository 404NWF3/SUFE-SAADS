# 更新——搭建框架

下面是我基于你原先的 LangGraph 主框架，以及你队友的 **AIBOM 驱动 uv 虚拟环境构建 Skill** 说明文档，整理出的 ​**更新版、详细、可落地的智能体搭建框架 V2**。

这版方案的核心变化只有一句话：

**你的系统不再是“一个生成攻击脚本的智能体 + 一个模糊的环境模块”，而是一个由 LangGraph 总控的安全评测工厂：外层固定主流程，内层只在高不确定性环节使用多智能体，环境构建正式下沉为独立 skill bundle。**

其中，环境部分明确采用你队友文档定义的工程边界：  
它是一个​**独立 skill 文件夹**​，一期只做 **Python + uv** 的最小可复现实验环境，不追求完整还原真实生产环境，且数据库读取统一经 `repository/service` 层而不是在 skill 中直接写 SQL。

---

# 一、更新后的总体定位

## 1. 系统目标

你的系统最终不是“写出一段攻击脚本”这么简单，而是要完成一个完整闭环：

**威胁情报 → 威胁理解 → 测试包生成 → 环境构建 → 运行攻击 → 收集证据 → 评分裁决 → 反思修复 → 经验沉淀**

这意味着它更像一个​**安全评测生产线**，而不是自由对话式 agent。

---

## 2. 更新后的总原则

### 原则 1：外层必须是强工作流

主流程固定，不让 agent 自己决定“下一步干什么”。

### 原则 2：只有三块做多智能体

保留你原先最合理的三块：

- 威胁理解
- 测试包生成
- 反思修复

### 原则 3：环境构建正式独立成 skill bundle

环境部分不再作为一个抽象“build\_env”黑盒，而是明确对接你队友的 `aibom_env_build_skill`​。  
这个 skill 的职责是：接收 AIBOM、攻击上下文、seed 资产和构建模式，解析组件、选模板、生成 uv 蓝图、写入 workspace、执行 `uv venv / uv sync / healthcheck`​，再统一返回 `ready / partial / failed` 的结果。

### 原则 4：把“测试包”和“可执行资产”分开

这是这版方案相对你原框架最重要的升级之一。

原来“生成测试包”之后直接“搭环境”，逻辑上是通的，但工程上会有一个隐含问题：

**测试包是抽象的攻击设计对象，不等于已经能在 uv workspace 里直接运行的文件。**

所以这版要把它拆清楚：

- ​`AttackTestPackage`：抽象测试设计
- ​`Runtime Attack Assets`：真正落到 workspace 中的 prompt、payload、driver script、config、seed 绑定结果

这样你整个链路才会真正可执行。

# 四、为什么要新增 `N9 materialize_runtime_attack_assets`

这是这版里我主动替你补上的关键节点。

## 原先框架的问题

你原来的框架里：

- N5 生成测试包
- N7/N8 搭环境
- 然后直接执行

但实际上：

- N5 产出的是“攻击设计”
- N8 产出的是“可运行环境骨架”

中间还缺一步：

**把抽象测试包编译为环境中的具体运行资产**

比如：

- ​`assets/payloads.json`
- ​`assets/prompts.txt`
- ​`scripts/dialogue_driver.py`
- ​`scripts/tool_case.yaml`
- ​`scripts/run_attack.py` 的参数化配置
- seed 资产挂载后的引用路径

所以 N9 必须存在。

## N9 的职责

它不是 agent，而是 skill/service：

- 把 `AttackTestPackage` 编译为具体文件
- 写进 `workspace_path`
- 和 `entry_command` 对齐
- 生成最终执行合同 `execution_contract`

这样 N10 才是真正“可执行”的。

- 可复现
- 可测试
- 可回归
- 可替换

- ​`executor`
- ​`schemas`
- ​`services`
- ​`tools`
- ​`templates`
- ​`registry`
- ​`tests`。

这说明它天然就应该是工程能力包，而不是再套一层 agent。

# 十一、失败与降级策略

你这个系统必须从一开始就能“优雅失败”。

## 1. 包有问题

回 N5：

- payload 太弱
- success criteria 不清
- evidence hooks 不够

## 2. 环境有问题

回 N7：

- AIBOM 解析失败
- 模板选错
- uv sync 失败
- healthcheck 失败

## 3. 运行时资产有问题

回 N9：

- prompt 写错路径
- dialogue script 未落盘
- entry command 与实际脚本不匹配

## 4. 知识不够

回 N3：

- threat understanding 置信度低
- 缺同类案例
- attack family 判错

## 5. 评分有争议
